❓ Help — Server settings (⚙️) and automations (🤖)

These options belong to the local server (server_max.py). They are saved in local/server_config.json and are only available when this page is opened through the local server (localhost). Every change is saved automatically.

Status

The lines at the top of the panel show whether the server is online, whether PyTorch (and CUDA) and onnxruntime were found, and what the background auto-fill is doing is shown in the 🤖 panel.

🚀 Startup (used the next time the server starts)

  • Check PyTorch at startup: the server looks for PyTorch / transformers and the GPU as soon as it starts, in the background, so tools like Florence-2 do not wait for that check when you open them. It does not load any model.
  • Check onnxruntime at startup: same idea for onnxruntime (used by the ONNX taggers).
  • Check package updates at startup: looks for newer versions of the Python packages. The answer is kept for 5 minutes. Turn it off if you are offline or want a faster start.

💾 Cache saves

  • Save big cache files in the background: large files (the Danbooru / e621 caches and the wiki texts can be tens of MB) are written by a background thread, so the page does not wait for the disk. Newer saves of the same file replace older pending ones, and a file is never read while its save is still pending.
  • Background from (KB): only saves bigger than this go to the background. Smaller ones are written right away.

🤖 Automations panel — Danbooru / e621 auto-fill (applies within seconds)

The 🤖 button next to ⚙️ holds everything the server does by itself. A background worker keeps the local Danbooru / e621 databases up to date, even with every page closed. It steps aside as soon as a tool really uses tags (a lookup, a fill, a save) and starts again a little after you stop. A page that is merely open does not block it. This switch is the same as 🤖 Auto-fill when idle in Tag Manager and Prompt Helper.

  • Safety trigger: the automations only run when tag manager.html or prompt helper.html is installed in this folder. Without them the master switch and the random download stay off (and cannot be turned on).
  • ▶ Check now: starts a check immediately, even when the automatic re-check is off. It still steps aside while a tool is using tags.
  • 🤖 Auto-fill enabled (master switch): turns the worker on or off. Turning it on starts it if the server was started with it off.
  • Automatic mode: with only the master switch on, the worker first completes what is saved, then walks the whole tag list of Danbooru and e621 by id (no page limit) and adds every tag with at least 1 post that is not saved yet. Tags with 0 posts are taken only when they are new aliases or deprecated tags. Afterwards it only looks for what was created since, sooner after a round that found tags and later after an empty one. Delays slow down by themselves when a site refuses a request. Everything else is in Advanced (manual tuning); turn off “Automatic speed and timing” there to use fixed numbers.
  • Start working when the server starts: off = the worker stays quiet after the server starts until you press Check now.
  • Keep downloading while a tool is open: the worker no longer stops when Tag Manager or Prompt Helper uses tags. It keeps downloading, but only into the small temporary files (local/autofill_temp/); the database files the page is using are not touched. After you stop using tags (and the “Resume after tag use” time passes) the temporary files are merged into the final files; an entry is only taken when it is not older than what the page saved meanwhile. Off = the old behavior (the worker stops while a tool uses tags).
  • Random tag download: on every re-check (the same timer, set below) the worker also looks at Random tags per round random tags of each site's tag list (in blocks of 100 from random places, one request after the other, spaced by that site's Delay between requests) and saves the tags that are not known yet, then fills their counts and wiki as usual. Set the quantity and the re-check time as you like. Off by default; with the re-check at 0 it runs only on Check now.
  • 🚦 Request queue (Advanced): the requests of the automatic work (auto-fill and random download) wait in one queue per site, so each one asks individually: one at a time, with the pause of the site (e621 at least 1 s). Tag Manager and Prompt Helper do not use the queue: they ask the sites directly, exactly as before, so they are never slowed down by it. The first thing the queue always does is check that the site is online (the same test as the dots); only when it is online the requests go on. When it is not, or when the site refuses a request, the queue waits (Wait when the site is down) and checks again. Turn it off to let the auto-fill ask the sites directly too.
  • Re-check when up to date (min): when everything is filled, the worker looks again for new tags after this many minutes (default 10). 0 = never by itself, only with Check now.
  • Danbooru / e621: choose which sites are filled.
  • Follow links of the saved wiki texts: wiki texts link to other tags ([[long hair]]). The worker downloads the linked tags that are not saved yet (count, category, wiki and text) and follows their links in turn. It is the same job as Fill wiki (recursive), but it never loses its place: the list of pending links is rebuilt from the saved texts each time. It needs Wiki text to be Full. Wiki pages that are not tags are remembered and not asked again.
  • Max. new tags from links (per site): stops following links after this many new tags. 0 means no limit.
  • Add new tags from the site catalog: when nothing else is left, walks each site's tag list from the most used tag down and adds the tags that are not saved yet.
  • Wiki text: how much of each wiki is saved. Same as the app follows the option in Tag Interrogator, Off saves none, Short saves a summary, Full saves the complete text (needed for following links; makes wiki_full.json grow).
  • Resume after tag use (s): how long to wait after the last time a tool used tags before the worker starts again.
  • Your e621 username: e621 asks every program that uses its API to say who runs it, otherwise it can block the requests (HTTP 403). It is sent as ModularAITools/1.0 (by your-name on e621). Fill in your own e621 name (an account is not required to exist, but a real name lets the site contact you if something goes wrong).
  • Tags per round: how many tags are handled at once. Smaller means gentler on the sites.
  • Delay between requests (ms), Danbooru / e621: pause between requests to each site (e621 allows about 1 request per second, so anything below 1000 ms is raised to 1000 ms). Do not set it too low: when a site refuses a request (HTTP 429) the worker waits 1 to 2 minutes and asks the same tag again.
  • Move to the final files every (s) (Advanced): Danbooru and e621 are processed at the same time. Each one writes what it learns, tag by tag, into its own small temporary file (local/autofill_temp/). This is how often both temporary files are moved together into the final files (cache, wiki texts, unknown tags), each file written in one piece. It also happens before the worker steps aside for a tool, and when the server stops. If the server or the PC stops suddenly, the temporary files are read again on the next start, so nothing is lost. When one site has nothing left to do, it simply stops and the other one carries on alone.

💡 A copy of each cache file is kept once a day in local/backups/ before the worker's first change of the day. The worker never overwrites a file that someone else changed while it was working: it reloads it instead.
